# 为什么需要宇树科技帮扶

PocketWorld 已经能在个人电脑上运行，但下一阶段的关键问题不是再写一个 demo，而是验证研究结论在更接近机器人导航的条件下是否成立。这正是个人资源和专业机器人平台之间的差距。

## 资源—增量对应关系

### GPU 云计算或训练资源

v1 的 fixed/adaptive horizon 配对矩阵和 bootstrap 摘要已经完成。下一步需要 GPU 扩展 seed，并运行观测噪声、延迟、速度估计误差和连续控制迁移的 formal experiments。资源对应的成果是版本化 paired JSON、统计区间、日志、图表和失败案例，而不是只保留一组手工挑选的数字。

### Unitree 仿真模型与开发资料

二维离散动作环境无法覆盖连续控制、传感器延迟、执行器动力学和机器人 footprint。Unitree 仿真资源可以让项目在不冒真实设备风险的情况下，验证 adaptive horizon 是否仍能根据模型不确定性调整预测范围，并与普通 MPC、局部规划和急停策略比较。

### 相机、传感器和受控测试设备

当前 uncertainty 主要来自 RGB 观测和学习模型。受控采集可以引入可记录的噪声、延迟和速度变化，检查 calibration 是否失效，以及 OOD shift detection 是否有实际价值。硬件只用于低速、隔离、可急停的观测/replay 实验，不直接把未验证策略交给自由运动机器人。

### 工程师指导与技术评审

项目最需要的不是替申请人写代码，而是审查：风险指标是否可观测、碰撞概率是否校准、比较是否公平、仿真到硬件的边界是否清楚、急停和安全屏障是否独立于学习策略。每次指导形成评审记录和修订后的协议，作为可检查的过程成果。

## 预期增量

帮扶前，项目能回答“在小型二维世界里如何观察 imagination gap”；帮扶后，项目应能回答“这些风险信号在连续控制和受控噪声下是否仍有预测价值”。如果答案是否定的，仍会得到清晰的迁移边界和一套公开的失败评测工具。
